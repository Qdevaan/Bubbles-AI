# Batch 3 — Analytics Read Endpoints + Feedback (v5 Port) — Design

**Date:** 2026-05-12 • **Author:** backend • **Status:** approved (pending spec review)

Ports the v2 (`legacy/server_v2/app/routes/analytics.py`) analytics surface into the v5 backend (`server/`), adapted to v5's architecture. v5 does **not** persist per-turn conversation content (`session_logs` / `sentiment_logs`), so the two transcript-dependent v2 behaviours are handled differently: `coaching_report` is generated by the post-session worker (which already receives the transcript) and the endpoint becomes a pure read; `session_replay` is deferred to a later batch that adds turn persistence.

---

## 1. Scope

**In scope — 5 endpoints + 1 worker enhancement:**

| # | Endpoint | Method | Behaviour |
|---|---|---|---|
| 1 | `/v1/save_feedback` | POST | Insert a `feedback` row; idempotent on `idempotency_key`. |
| 2 | `/v1/session_analytics/{session_id}` | GET | Return the cached `session_analytics` row. 404 if not yet computed. |
| 3 | `/v1/coaching_report/{session_id}` | GET | Return the cached `coaching_reports` row. 404 if not yet computed. |
| 4 | `/v1/digest/{user_id}` | GET | Recent sessions + pending tasks + top entities + recent highlights over `?period=day\|week`. |
| 5 | `/v1/communication_trends/{user_id}` | GET | `session_analytics` rows aggregated by ISO week over `?weeks=N` (1–52, default 8). |
| W | `compute_session_analytics` worker | — | Also computes a `session_analytics` metrics row and a `coaching_reports` row from the transcript it already receives. |

**Out of scope (documented as follow-ups in `Documentation/server-vs-server_v2-review.md` §5):**
- `GET /v1/session_replay/{session_id}` — needs a per-turn store (`session_logs`); bundle with that future work.
- Per-turn-derived columns of `session_analytics`: `average_latency_ms`, `avg_advice_latency_ms`, `avg_sentiment_score`, `dominant_sentiment` — left NULL until v5 captures per-turn latency/sentiment.
- `sentiment_trend` array in the `session_analytics` response — empty until `sentiment_logs` is populated by v5.
- Wiring an actual caller for `enqueue_session_analytics` (end_session → enqueue) — currently the function exists but nothing invokes it; that's a separate change.
- No new Alembic migration: `session_analytics`, `coaching_reports`, `feedback` already exist in the live Supabase schema (`Documentation/db_schema.sql`).

## 3. Repos

### 3.1 `server/src/bubbles/db/repo/analytics.py` (new)

Module docstring, `from __future__ import annotations`. Column constants `_SA_COLS`, `_CR_COLS`; private hydration helpers `_session_analytics(row)`, `_coaching_report(row)` (coerce array NULLs to `[]`, parse `report_content`). Async functions, `conn: asyncpg.Connection` first-positional, rest keyword-only.

- `async def get_session_analytics(conn, *, session_id: UUID) -> SessionAnalytics | None`
  `SELECT {_SA_COLS} FROM session_analytics WHERE session_id = $1`.
- `async def upsert_session_analytics(conn, *, session_id, user_id, total_turns, user_turns, others_turns, llm_turns, user_word_count, assistant_word_count, total_duration_seconds, memories_saved, events_extracted, highlights_created, topic_summary) -> None`
  `INSERT INTO session_analytics (...) VALUES (...) ON CONFLICT (session_id) DO UPDATE SET ... , computed_at = timezone('utc', now())`. Per-turn columns (`average_latency_ms`, `avg_advice_latency_ms`, `avg_sentiment_score`, `dominant_sentiment`) are **not** written — they stay at their DB defaults (NULL).
- `async def get_coaching_report(conn, *, session_id: UUID) -> CoachingReport | None`
  `SELECT {_CR_COLS} FROM coaching_reports WHERE session_id = $1 ORDER BY generated_at DESC LIMIT 1`.
- `async def upsert_coaching_report(conn, *, session_id, user_id, model_used, user_talk_pct, others_talk_pct, key_topics, key_decisions, action_items, follow_up_people, filler_words, filler_word_count, tone_summary, engagement_trend, suggestions, strengths, areas_of_improvement, report_text, report_content) -> None`
  Idempotent **without** `ON CONFLICT` (the live `coaching_reports` table has no unique constraint on `session_id`): `UPDATE coaching_reports SET ... WHERE session_id = $1`; if `UPDATE`'s status reports 0 rows affected, `INSERT INTO coaching_reports (...) VALUES (...)`. Runs inside the caller's transaction (the worker's `UnitOfWork`). See §3.3 for why.
- `async def trends_since(conn, *, user_id: UUID, since: datetime) -> list[asyncpg.Record]`
  `SELECT session_id, total_turns, user_word_count, assistant_word_count, avg_sentiment_score, total_duration_seconds, computed_at FROM session_analytics WHERE user_id = $1 AND computed_at >= $2 ORDER BY computed_at DESC`. (ISO-week grouping is done in the route handler — pure Python, easy to unit-test.)

### 3.2 `server/src/bubbles/db/repo/feedback.py` (new)

- `async def find_by_idempotency_key(conn, *, key: str) -> UUID | None`
  `SELECT id FROM feedback WHERE idempotency_key = $1`.
- `async def insert(conn, *, user_id, feedback_type, session_id=None, log_id=None, consultant_log_id=None, value=None, rating=None, comment=None, idempotency_key=None) -> Feedback`
  `INSERT INTO feedback (...) VALUES (...) RETURNING {cols}`. (No `_COLS` constant beyond a local string; one `_row` helper.)

### 3.3 `coaching_reports(session_id)` uniqueness

Live `coaching_reports` has **no** unique constraint on `session_id` (it's a plain nullable column). To make `upsert_coaching_report` idempotent we need one. Two acceptable options — pick the second:

- ~~Add a `CREATE UNIQUE INDEX` migration~~ — but the live table may already have multiple rows per session from v2, so a unique index could fail to build.
- **Repo-level upsert without ON CONFLICT:** `upsert_coaching_report` does `UPDATE ... WHERE session_id = $1; if rowcount == 0: INSERT ...` inside the caller's transaction (the worker already wraps its writes in a `UnitOfWork`). Safe against concurrent runs because the worker is idempotent per session (job id keyed on session). This avoids any schema change.

Document this choice in the repo docstring.

### 3.4 Digest reads

Digest needs four small reads. Add to **`analytics.py` repo** (they're digest-specific aggregates, not general session/entity ops):

- `async def digest_sessions(conn, *, user_id, since: datetime, limit: int = 20) -> list[asyncpg.Record]` — `SELECT id, title, mode, status, created_at, summary FROM sessions WHERE user_id = $1 AND created_at >= $2 AND deleted_at IS NULL ORDER BY created_at DESC LIMIT $3`.
- `async def digest_pending_tasks(conn, *, user_id, limit: int = 10) -> list[asyncpg.Record]` — `SELECT id, title, status, priority FROM tasks WHERE user_id = $1 AND status = 'pending' ORDER BY created_at DESC LIMIT $2`.
- `async def digest_top_entities(conn, *, user_id, limit: int = 5) -> list[asyncpg.Record]` — `SELECT id, display_name, entity_type, mention_count FROM entities WHERE user_id = $1 AND deleted_at IS NULL ORDER BY mention_count DESC NULLS LAST LIMIT $2`.
- `async def digest_recent_highlights(conn, *, user_id, since: datetime, limit: int = 5) -> list[asyncpg.Record]` — `SELECT id, highlight_type, title, body FROM highlights WHERE user_id = $1 AND created_at >= $2 ORDER BY created_at DESC LIMIT $3`.

`session_count` for the period = a separate `SELECT count(*) FROM sessions WHERE user_id = $1 AND created_at >= $2 AND deleted_at IS NULL` (the recent-sessions list is capped at 20, so derive the true count separately).

## 4. Worker enhancement — `server/src/bubbles/workers/jobs/compute_session_analytics.py`

The job already: generates `title`/`summary`/`highlights` and writes them. Add **two more steps**, each independent and fault-isolated like the existing ones.

### 4.1 Transcript parsing helper — `server/src/bubbles/core/transcript.py` (new, pure)

The transcript v5 passes is the plain text accumulated client/STT side. v2 relied on structured `session_logs(role)`; v5 must infer roles from line prefixes. Convention used by v5 prompts (`render("wingman/...jinja", transcript=...)`) is lines like `User: ...`, `<Name>: ...`. Implement a small, well-tested parser:

```python
@dataclass(frozen=True, slots=True)
class TranscriptStats:
    total_turns: int
    user_turns: int
    others_turns: int       # non-"User", non-"AI"/"Assistant" speakers
    llm_turns: int          # "AI" / "Assistant" / "Bubbles"
    user_words: int
    assistant_words: int    # words in llm turns
    others_words: int

def parse_transcript(transcript: str) -> TranscriptStats: ...
```

Rules: split on lines; a "turn" = a line matching `^\s*([^:]{1,40}):\s*(.*)$`. Speaker classification: case-insensitive — `user`/`me`/`you` → user; `ai`/`assistant`/`bubbles` → llm; anything else → others. Lines without a speaker prefix attach to the previous turn (continuation). Word count = whitespace-split token count of the content. Empty/garbage transcript → all zeros. (No filler-word counting here — that lives in the coaching-report LLM output, mirroring v2.)

### 4.2 Step: write the `session_analytics` metrics row

After the title/summary/highlights block, inside the same `UnitOfWork`:

```python
stats = parse_transcript(transcript)
sess_row = await uow.conn.fetchrow(
    "SELECT start_time, ended_at, end_time FROM sessions WHERE id = $1", sess_uuid
)
duration = None
if sess_row is not None:
    end_ts = sess_row["ended_at"] or sess_row["end_time"]
    if end_ts is not None and sess_row["start_time"] is not None:
        duration = max(0.0, (end_ts - sess_row["start_time"]).total_seconds())
memories_saved = await uow.conn.fetchval(
    "SELECT count(*) FROM memory WHERE session_id = $1", sess_uuid
) or 0
events_extracted = await uow.conn.fetchval(
    "SELECT count(*) FROM events WHERE session_id = $1", sess_uuid
) or 0
highlights_created = len(highlights)
await analytics_repo.upsert_session_analytics(
    uow.conn,
    session_id=sess_uuid, user_id=user_uuid,
    total_turns=stats.total_turns, user_turns=stats.user_turns,
    others_turns=stats.others_turns, llm_turns=stats.llm_turns,
    user_word_count=stats.user_words, assistant_word_count=stats.assistant_words,
    total_duration_seconds=duration,
    memories_saved=int(memories_saved), events_extracted=int(events_extracted),
    highlights_created=highlights_created,
    topic_summary=summary or None,
)
```

(`events` table exists in v5's baseline; `highlights` table exists and is written above.) This step is **not** wrapped in its own try/except for `UpstreamUnavailable` — it makes no LLM calls — but a `try/except Exception` around it that logs and continues keeps a parsing edge case from killing the whole job.

### 6.1 `POST /save_feedback`
```python
@router.post("/save_feedback", response_model=SaveFeedbackResponse)
async def save_feedback(body: SaveFeedbackRequest, user: CurrentUserDep, pool: PoolDep) -> SaveFeedbackResponse:
    if body.idempotency_key:
        async with transaction(pool) as conn:
            existing = await feedback_repo.find_by_idempotency_key(conn, key=body.idempotency_key)
        if existing is not None:
            return SaveFeedbackResponse(status="ok", idempotent=True)
    rating = body.value if body.feedback_type == "star" else None
    async with UnitOfWork(pool) as uow:
        try:
            await feedback_repo.insert(
                uow.conn, user_id=UUID(user.id), feedback_type=body.feedback_type,
                session_id=body.session_id, log_id=body.session_log_id,
                consultant_log_id=body.consultant_log_id, value=body.value,
                rating=rating, comment=body.comment, idempotency_key=body.idempotency_key,
            )
        except asyncpg.UniqueViolationError:        # race on idempotency_key
            return SaveFeedbackResponse(status="ok", idempotent=True)
    return SaveFeedbackResponse(status="ok")
```
Ownership: `feedback.user_id` is always the authenticated user — no `require_ownership` needed (the path has no `{user_id}`). Comment is length-bounded by the schema; no extra sanitization (v2's `sanitize_input` was an HTML-strip; the comment is never rendered as HTML by v5). Document that decision in the handler.

### 6.4 `GET /digest/{user_id}`
```python
@router.get("/digest/{user_id}", response_model=DigestResponse)
async def get_digest(user_id: UUID, user: CurrentUserDep, pool: PoolDep,
                     period: Literal["day", "week"] = "week") -> DigestResponse:
    require_ownership(user, str(user_id))
    days = 1 if period == "day" else 7
    since = datetime.now(UTC) - timedelta(days=days)
    async with transaction(pool) as conn:
        sessions = await analytics_repo.digest_sessions(conn, user_id=user_id, since=since)
        count = await conn.fetchval(
            "SELECT count(*) FROM sessions WHERE user_id = $1 AND created_at >= $2 AND deleted_at IS NULL",
            user_id, since,
        ) or 0
        tasks = await analytics_repo.digest_pending_tasks(conn, user_id=user_id)
        entities = await analytics_repo.digest_top_entities(conn, user_id=user_id)
        highlights = await analytics_repo.digest_recent_highlights(conn, user_id=user_id, since=since)
    return DigestResponse(
        period=period, user_id=user_id, sessions_count=int(count),
        recent_sessions=[DigestSession(**dict(r)) for r in sessions],
        pending_tasks=[DigestTask(**dict(r)) for r in tasks],
        top_entities=[DigestEntity(**dict(r)) for r in entities],
        recent_highlights=[DigestHighlight(**dict(r)) for r in highlights],
    )
```
(Spreading `dict(record)` works because the SELECT column names match the schema field names exactly — keep them aligned.)

### 6.5 `GET /communication_trends/{user_id}`
```python
@router.get("/communication_trends/{user_id}", response_model=CommunicationTrendsResponse)
async def get_communication_trends(user_id: UUID, user: CurrentUserDep, pool: PoolDep,
                                   weeks: int = Query(8, ge=1, le=52)) -> CommunicationTrendsResponse:
    require_ownership(user, str(user_id))
    since = datetime.now(UTC) - timedelta(weeks=weeks)
    async with transaction(pool) as conn:
        rows = await analytics_repo.trends_since(conn, user_id=user_id, since=since)
    trends = _group_by_week(rows)        # pure helper in this module
    return CommunicationTrendsResponse(
        user_id=user_id, weeks_requested=weeks, weeks_available=len(trends), trends=trends,
    )
```
`_group_by_week(rows: list[asyncpg.Record]) -> list[WeeklyTrendOut]`: key each row by `r["computed_at"].isocalendar()` → `f"{iso_year}-W{iso_week:02d}"`; accumulate `sessions += 1`, `total_turns += r["total_turns"] or 0`, `user_words += r["user_word_count"] or 0`, `ai_words += r["assistant_word_count"] or 0`, `total_duration_seconds += float(r["total_duration_seconds"] or 0)`, and track sentiment as `(sum, n)` over non-NULL `avg_sentiment_score` → `avg_sentiment_score = sum/n if n else None`. Return sorted by week descending (newest first). Pure → unit-tested.

## 7. Errors

- `404 NOT_FOUND` (`NotFound`) — `session_analytics` / `coaching_reports` row absent (not yet computed, or bad id).
- `403 FORBIDDEN` (`require_ownership`) — caller ≠ resource owner (analytics row's `user_id`, or `{user_id}` path).
- `422` — FastAPI validation (bad `period`/`weeks`/`feedback_type`/`value` range) — handled by Pydantic, no code needed.
- No `UpstreamUnavailable` on the read endpoints (no LLM calls); the worker handles its own LLM failures and simply doesn't write the report row, so the endpoint stays 404 until a successful run.
